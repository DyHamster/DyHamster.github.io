# 龙猫森林主页：桌面增量优化

最终技能状态：`GATE: OPEN 35 (rounds used up)`。35 项开放记录及 5 项具体豁免见 [逐项说明](desktop-polish/skill-review.md)；项目检查及真实浏览器功能验收已通过。

本轮保留已有 React / Vite / HashRouter、Markdown 内容源、五个栏目、角色图集、可取消场景控制器和常驻音乐组件。没有部署远端。

预览：<http://127.0.0.1:5183/>。重启方式：`npm run build`，然后 `npm run preview -- --host 127.0.0.1 --port 5183`。

## 排版与内容

- 桌面容器最大 1280px，两侧至少留 96px；导航、首屏、栏目标题、卡片和结尾共用 `.shell`，背景继续全幅。
- 主要介绍 17–18px、导航 15px、常用辅助信息 13px；搜索输入 16px，正文 18px / 1.95 行高。移除或隐藏没有信息价值的英文装饰标签。
- 米白 `#f6f5eb` 上，正文 `#263d30` 对比度 10.70:1，辅助字 `#536654` 为 5.65:1。深色纸面 `#203027` 上，正文和辅助字分别为 11.52:1、7.91:1。这些是纯色配对计算值，背景插画另通过遮罩和实际截图检查。
- 首屏采用 `100svh` 与高度响应字号，取消 820px 的固定最小高度；1366×768 的姓名/身份、标题、介绍、入口、龙猫及滚动提示均位于首屏。
- 首页直接呈现南京大学学生、强化学习、数学基础、论文与阅读等信息。主题入口读取既有栏目配置，最近更新和精选继续读取真实公开内容。
- 当前内容源只有三个草稿模板，没有公开文章或实验。保持草稿状态，没有为了展示而发布示例。空状态收紧，并提供实际主题入口。
- 桌面音乐停靠在左侧安全边缘；手机上收至导航顶部，避免滚动时遮住卡片。最小点击区域 44px，播放失败提示在 4.5 秒后收起。默认首次安静进入，仍可通过设置选择“伴着音乐进入”或“安静进入”。播放、暂停、音量、偏好与后台处理逻辑保留，跨栏目不重新挂载音频。

## 角色与场景

原来内页共用右下角落点；现在每个地点有独立地面锚点、比例、朝向、构图及阅读泊位。

| 地点 | 抵达脚底位置，桌面视口百分比 | 待机朝向 | 场景联系 |
| --- | --- | --- | --- |
| 首页 | 81%, 83% | 向右 | 大树溪边，坐下休息 |
| 笔记 | 76%, 46% | 向右 | 镜头抬至树根草地，站在笔记桌左侧 |
| 文章 | 87%, 45% | 向左 | 小屋门廊、书架与灯光 |
| 实验 | 79%, 49% | 向右 | 树根草地，面向实验工作台 |
| 关于 | 86%, 47% | 向左 | 傍晚小屋门廊与暖光 |

首页到笔记作为标准：约 0–289ms 醒来/起身，289–1277ms 沿曲线前往目标，约 760ms 提交新内容并与场景溶解同步，1277–1520ms 停步、进入待机。步行帧由曲线路程推进，脚底基线统一为图集单元的 y=315px，身体重心也做了逐帧水平校准。

五处背景仍使用两张已有去角色底图；通过镜头纵向偏移、裁切、光线和道具区分地点。角色只有一个独立实例，不会与底图龙猫重影。到达后仍在场景地面停留；阅读正文或向下滚动时，收至右侧安全边缘。1024px 下实测角色左缘 x=936px，正文右缘 x=928px；音乐右缘 x=76px，正文左缘 x=96px。

改选目的地保留当前角色位置和背景混合权重，并取消旧时间线。搜索、标签、分页、同栏目详情更新不重播跨场景转场。减少动态效果时使用约 110ms 的简洁切换。素材加载失败仍有代码角色与正常导航。

## 本轮验证

项目检查：`npm run lint`、`npm run check`、`npm test`（17 项）、`npm run build`。

浏览器实际操作：

- 1440×900、1366×768、1920×1080、1024×768 首页首屏边界与文字；五栏目页首、地标及导航。
- 全部 20 条有方向的跨栏目路径；快速连续改选、前进后退、直接打开与刷新；持续存在的角色和音频节点。
- 实际音频播放进度跨栏目增长；播放/暂停、音量 35%、设置面板与 Escape；深浅主题切换后等候颜色稳定再截图。
- 12 篇临时笔记、2 篇临时长文、1 个临时实验验证搜索、分类、标签、分页、公式、代码、图片、目录、上下篇及体验入口。已全部移除；长文截图明确标记为本地验证。
- 1024px 阅读安全边缘、向导收起/展开、390px 与 320px 基本导航、横向溢出、减少动态效果、图片和图集请求失败降级。
- 键盘实际 Tab / Enter、跳到正文与焦点边框。原始验证结果见 `desktop-polish/*verification.json`。

截图：`desktop-polish/home-1440x900.png`、`home-1366x768.png`、`home-1920x1080.png`、`home-1024x768.png`；其他栏目、深色与手机截图在同一目录。`home-to-notes.gif` / `.webp` 来自浏览器连续 screencast，保留真实帧间时间，没有音轨。

## design-taste-frontend 的适用范围

使用技能的字体层次、对齐、克制交互、截图、一致性、性能和 gate 工作流。从 `src/vendor/taste-motion/` 原样接入其微交互层；森林跨页叙事继续由现有 React 控制器管理。

按用户要求保留个人博客的自然页面长度和诗意主标题，不采用商业官网的商品/价格/销售转化、整节固定一屏、真实照片替换插画、随机更名或 `.example` 联系方式规则。哈希路由由 React 管理，`#/notes` 是可用地址，不能按照静态 HTML 锚点处理。

技能布局工具的原始运行因找不到它约定的 `.wrap/.container` 而返回非完整结果，随后报 `sections is not iterable`。本项目使用既有 `.shell` 和路由内容包装层，未为检查器改写页面结构；实际尺寸与操作由独立浏览器验证补齐。通用一致性报告中的哈希链接、商业标题、固定整屏、菜单按钮识别、打包后的 motion.css 识别等不适用或误判均保留原始记录，没有修改检查器或隐藏检查项。

性能报告区分实际问题与场景机制：补齐了背景图宽高；跨场景底图预载用于避免切换闪烁，五层实际复用两张图片；手机底图为覆盖裁切而保留 900px 宽；图集有四列、单帧 320px，阅读缩小时仍共享同一图集。这些会被普通照片预算标记为非懒加载/尺寸偏大。最终性能检查仍有 3 个通用照片预算 FAIL（两种宽度下的常驻场景非懒加载、手机覆盖裁切图尺寸），已保留原始结果；图片宽高缺失已为 0。桌面总传输约 1.22MiB、手机约 0.77MiB；无 WebGL、无外部字体请求，实际加载体积与时序以 `desktop-polish/performance.json` 为准。

最终 gate 原始状态及全部开放项见 `desktop-polish/skill-gate.txt`；此状态不代替上面的项目检查与实际操作验证。
